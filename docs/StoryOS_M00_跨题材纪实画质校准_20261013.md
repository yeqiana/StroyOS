# StoryOS M00 跨题材纪实画质校准（2026-10-13）

## 目标与边界

M00 只规范**照片如何被故事内摄影者真实记录**，不规定**镜头中必须出现什么**。参考图是对自然光、成像设备、取景、人物和环境真实性的样本，不是剧本、动作库、固定道具库或固定场景库。

静止、微动作、日常活动、快速运动、空间异常等均可属于 M00；动态感应由真实事件产生，不得强行让每张照片模糊、倾斜、奔跑或出现戏剧冲突。只根据 Story、Storyboard、Resolved Frame Contract 决定具体事件、角色数量、地点、道具、视角和镜头强度。

## 权威关系

- `standards/visual_profiles/M00_MP4_网吧_流水席_旧数码.json` 是已有母风格权威，本轮**不修改其内容和 SHA**。
- `standards/capture_grammars/FIRST_PERSON_CASUAL_SNAPSHOT_V1.json` 规定摄影者身份、站位、真实拍摄行为；允许合法的其他 Capture Grammar 配置。
- `standards/capture_profiles/CP01..CP08` 规定设备物理，**M00 不暗示所有故事默认 iPhone 6 或旧数码**。
- `visual_profile_bridge_v224.py` 将 M00 原有的 `anti_homogeneity` 规则编入文本合同，保持源文件不变。
- `m00_style_guard.py` 从锁定的 Visual Contract 选取少量真实性规则，追加在 Controller 已压缩的 scene_prompt 后，并进入规范化 Payload Request SHA / fingerprint。它不增加或改写分镜事实。
- `visual_lock_baseline_gate.py` 的两种 Critic 提示词增加“静态可合格、严禁复制参考动作、缺陷需物理原因”的审片要求；这不是取消像素审核。

## 本轮验证

```powershell
python scripts/storyos_m00_fast_test.py
```

仅执行 stdlib/unittest；不连接 MySQL、不调用任何图片 Provider、不消耗生成 Attempt。覆盖：母风格 SHA 不变、跨多场景/动作约束一致、静态镜头合格、非 M00 不受影响、伪造 guard 拦截、最终 Payload 的 SHA 和 fingerprint 验证。

上述快速测试是必要条件，而非画质充分证明。正式图片风格需要先完成 4 帧 Visual Lock 的真实像素评审；按实际题材挑选代表样本，不固定为用户参考图中的动作。

## 后续审查项

1. 参考图作为 `capture_style` 引用显式 SHA 绑定，审计其实际是否进 Provider；不要自动把参考图里的人物动作与地点传给 Story。
2. 建立跨题材实际像素盲评基线，评委优先辨别拍摄真实性，而不是“越戏剧化越好”。
3. 在不改变旧 Episode 源资产 SHA 的前提下，再考虑未来 M00 版本升级和基准集版本化。
