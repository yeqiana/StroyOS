# StoryOS M00 四槽真实成像修订 R5（2026-10-13）

这是基于 C01–C04 四张真实 PNG 评审的代码闭环，不是四张图片已达到最终画质的证明。本轮不修改历史 Episode、标准设备 JSON SHA、参考图原件或 MySQL。

## 槽① 设备物理真实透传

m00_capture_profile_contract 依据 Episode 的 capture_profile，从 CP01–CP08 注册表读取 JSON 并计算 SHA；auto 仍使用配置默认 CP01。CP02 的 device_dependent 只做有条件的年代物理解释；CP03 明确小传感器弱光噪声、较低动态范围、旧 JPEG，但不强制模糊/损伤。visual_profile_bridge_v224 将设备物理编进 Visual Contract；m00_style_guard 投影到最终 Provider scene_prompt，并参与现有 Payload SHA/fingerprint。风格参考图不授权复制人物、动作或地点。

## 槽② 分镜可见证据

m00_scene_fidelity_guard.enforce_event 将锁定的原始帧事件重新绑定到最终 Prompt，防止 Controller 把异常事件遗漏并替换成生活照。“由故事定义的异常”等占位无法生成可验证画面；仅对显式未完成占位作预生成阻断，不把所有合法异常/静态剧情误伤。仍须实际像素语义 Critic 才能认定事件达标。

## 槽③ 动作物理

enforce_motion 提醒手/物接触、身体重心、物体移动和摄影者抓拍时机；不限定任何具体动作。静态场景不得强制运动、倾斜、模糊或人为脏画质。

## 槽④ 连续性及 Codex 真实回执

语义 Critic 对相邻帧逐项复核人物服装、摄影者可达机位、道具状态、时间天气和故事信息变化。m00_calibration_receipts 只读核对 Test-only PNG SHA/尺寸、正常 Codex 结果及超时后同线程恢复的结果。C03 类型必须保留 IMAGE_RECOVERED_AFTER_RUNNER_TIMEOUT，不得冒充正常返回或自动重试；报告绝不授予正式 Visual Lock、发布或 Attempt 权威。
