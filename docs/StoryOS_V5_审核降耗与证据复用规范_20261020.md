# StoryOS V5：审核降耗与证据复用规范（2026-10-20）

本规范是现有生产流程收敛，不增加新的工作流引擎、调度器、审核权威或状态机。

## 审核与校验职责

1. 质量审核：Story Review、Visual Lock、正式 Frame Semantic Review、Release Critic 保留唯一权威。FAST Scout/Shadow 仅为建议或研究数据，不能产生正式 PASS。
2. 技术校验：SHA、Frame Contract、MySQL Generation Attempt、Provider Receipt、Writer/Lease Fence、Final Candidate Snapshot 保留；不以质量审核精简为由移除。
3. 每次质量判断基于现有资产/契约指纹；只有 SHA、上下文与绑定的模型策略一致的 PASS 可复用。证据失效、缺失或 UNKNOWN 必须如实阻断/恢复。

## 精简后的生产链

创意/故事/分镜与 Story Lock → PREIMAGE/角色/环境/帧契约校验 → Visual Lock 校准图评审 → 并发首轮生图 → 正式帧级审核 → 一次按需局部 Repair Wave → 增量复审 → 跨分片连续性闭环 → 字幕/封面/发布文案 → Release Critic → Final Candidate Snapshot → Release Lock → PUBLISH_READY。

- 首轮正式帧审核必须建立完整的评审基线；任何尚未审核的新剧不允许用 PATCH 冒充首审。
- 已有可复用 PASS 帧时，局部图片返修只让脏帧及必要邻近上下文重新接受模型裁决；脏帧比例大于 25% 本身不触发全量重审。
- 上游故事、帧契约、全局视觉上下文漂移仍需触发正确范围的重新审核。
- 发布 Critic 只审核最终发布资产的新问题，不以“再确认一下”为由重审整个故事或所有图片。
- 自动修复每帧最多一次，二轮内容失败按当前 NEEDS_USER/直接用户明确接受已知缺陷通道处理，严禁静默低分通行和盲目第三次付费生图。
- 429、超时及 UNKNOWN 走技术/结果未决恢复，不消耗内容返修预算，也不能虚构成功回执。
- story/preimage/final 语义 Shadow 作为研究路径默认关闭，按授权抽样再启用，不得写正式权威。
- StoryOS 的正式交付仍是图文，不默认图片转视频。

## 可观测性与极速验收

现有 episode_performance.py 记录 FULL/PATCH 审核耗时 Span。通过只读 review_efficiency_report.py 获取当前增量审核计划、脏帧数、复用数、复用率、审核 Span 次数和重叠去重的墙钟耗时；Span 不等于经 Provider 证明的模型调用次数，未知必须显示 UNKNOWN，不能猜测成本。

本轮离线极速入口：python scripts/storyos_review_efficiency_fast_test.py。

新旧剧集的实际提速应通过同一帧集合的真实运行回执验证，不能以模拟测试推断实际生产速度。本规范不授权任何付费生图或删除生产安全 Gate。
