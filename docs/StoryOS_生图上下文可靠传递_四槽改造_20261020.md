# StoryOS 生图上下文可靠传递与分镜可执行性：四槽改造方案

> 日期：2026-10-20 · StoryOS · 基线 `origin/story-platform-v3-rever`（创建时 df79919a）  
> 约束：方案先落地；本轮离线验证，不授权任何额外付费图片。

## 现状

`frame_contract.compile_frame` 汇聚故事分镜、人物与 POV、外观服装、镜头/摄影、世界环境、相邻状态、视觉风格。文本型 `image_payload_controller` 读完整 `frame_prompt_contract`，但原生图片工具只直接收到 Controller 改写的 `scene_prompt`、一些确定性的 M00 附录、图片参数及至多两张参考图。完整 Frame Contract **未原样传给图片工具**，因而有硬约束被转述丢失的风险。

《失物归还的那扇门》20 帧首轮审核中 19 帧未通过，常见问题涉及跨帧视觉记忆、服装、动作、人物、POV。第 02 帧同瞬间“手持手机+签领单据+回头”也存在拍摄物理可执行性风险。**这是工程假设，需要测试与对照，不将相关性冒充因果。**

## 总体设计

```text
冻结 Story / Storyboard / Frame Contract
  ├─ scene_prompt → Image Controller 只可优化软性描述
  ├─ critical_obligations → 确定性提取、不可改写、版本/SHA 绑定
  └─ reference_images → <=2、角色/用途/原图 SHA 绑定
→ Payload Request 的指纹涵盖实际送出的全部语义
→ 原生 Codex stdin = scene_prompt + critical_obligations + 风格/动作保护 + 参考图角色
→ -i 图片附件 → image_generation → 原 Gateway / Attempt / Review
```

## 四槽交付

### ① P0 硬约束直达图片 Payload

范围：`image_worker_pool.py`、`image_payload_request.py`、`image_payload_controller.py`、`codex_subscription_image.py`。从冻结的 Frame Contract 确定性取出本帧**人物身份、外观衣着、摄影者/POV、主要可见事件、时空约束**，构建有边界且有限长的不可变附录，避免重复注入 M00 已有的原始场景/摄影规则。Controller 仍可改写软性 scene_prompt，但不能删除关键事实。SHA 改变必须改变请求指纹。验收：模拟 Controller 删掉人物衣着/机位后，最终 transport 输入仍有绑定约束；错 SHA 必须拒绝。

### ② P0/P1 参考图片真实绑定

范围：`reference_arbitrator.py`、`image_scheduler.py`，如有必要加入窄范围附件验证。最多两张；人物身份优先；两个必要人物锚点不得被风格/道具挤掉。原图路径、SHA、kind/role 与临时压缩附件按顺序一致；缺图不伪造。验收：两人互动、优先级冲突、缺失锚点与双图上限离线快速用例。

### ③ P1 单帧静态拍摄可执行性

优先利用 `capture_event` / `shot_progression` / `frame_directive` 的**结构化事实**判断同瞬间明显不可执行的摄影/动作约束，返回明确冲突码；有歧义时仅提供提示，不靠泛化词表误阻断，不擅自改写冻结故事，不增加 LLM Critic。验收：可证明物理冲突被捕获，合法动作/普通静态帧不误拦。

### ④ P1 融合回归与效率证据

负责离线端到端用例：Frame Contract → Controller → Payload → native stdin、真实参考图绑定、技术失败/UNKNOWN 不重试、图片 Gateway 和预算不变。各槽 RED→GREEN，运行对应系统测试与 `python scripts/storyos_autonomy_fast_test.py --slot production-regression`；合并前 `--slot all`、整体 `--slot all --stress`。记录上下文长度、调用量、首轮失败类型、返修和实际耗时；无真实生产 A/B 时不可声称提速已经验证。

## 安全边界与合并方式

- 不新增审核节点，不放宽现有 Review Authority/NEEDS_USER，不新增独立调度器或视频管线，不恢复 OpenCodex。
- 维持原有全局 5 图共享容量、MySQL Generation Attempt、正式 Gateway、Runner 回执、请求指纹、Provider RAW 真实 SHA；429/UNKNOWN 不盲重试。
- 主工作区有未提交变更，仅在独立 worktree 开发；先提交本 MD 再建立四槽，共享该基线；四槽隔离编辑文件。
- 各槽分开中文提交，正文格式：模块名称行、空行、StoryOS；集成后重跑回归，远端有新提交先核查，不强制推送，不危险清理 Worktree。
- 不触碰 aigc-dali-cat 及已运行服务；真实图片 Canary 需单独明确授权。

### 本轮范围与剩余风险

- 当前版本通过确定性文本投影保障 Frame Contract 的主要人物/衣着/POV/拍摄事件进入 **原生 Codex 实际生图提示词**；只承诺信息送达，不承诺生成模型必然遵循。
- 参考图持续最多两张；保持图片原始 SHA 作为权威，压缩后的附件属于传输代理。
- 单帧可执行性检查只对明确的结构化冲突阻断，不对“P01签字并手持相机”等自由叙述拍摄动作做不可靠的猜测。高频失败故事需要未来上游补充可证实的动作预算结构化字段，避免误拦。
- 已有 UNKNOWN/429 第 02 帧仍被 MySQL Authority 阻断，本轮不更改、不发起额外生图、不冒称 PUBLISH_READY。
- 不新增审核；远端 V5 已优化冗余审核，勿重复造轮子。
