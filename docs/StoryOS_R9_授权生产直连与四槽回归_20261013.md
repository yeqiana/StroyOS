# StoryOS R9 · 获授权后的真实生产与四槽极速验收（2026-10-13）

## 实际生产观测（与 Mock 分开）

用户明确授权正式生产后，在**主工作区**通过官方原生入口对 `episodes/15_天界生活日常/01_天界普通女生的一天` 执行 **一次**：

```powershell
python scripts/storyos_codex_managed.py start "episodes/15_天界生活日常/01_天界普通女生的一天" --ack-real-production
```

本机确实启动 Windows Task Scheduler Driver，出现 PID 70088、心跳 LIVE、运行态 `RETRY_WAIT`，随后退出码 3。使用正式 `runtime.env` 取得的 MySQL Stage 仍为 `STORYBOARD_LOCKED`；`TB_GENERATION_ATTEMPT` 仍是 **0 条**、无活动或 UNKNOWN。因此**没有可信的付费出图或首帧成功证据**。直接调用 `runtime_driver.py status` 不加载正式数据库设置，曾误连默认端口，应改用 `scripts/storyos_production_env.py` 或本轮只读探针，禁止凭误连接重试付费生成。

发现 `story_os.py next-action` 的 `PRODUCT_REVIEW` 被遗留的 `story-semantic-critic-shadow` / `WORK` host request 占据。该 shadow 是非权威评测，不能永久阻塞改为 `CODEX_MANAGED` 的原生生产；真正的 `story-semantic` 正式审核仍必须执行，不得跳过。R9 在 `next_action.py` 严格限于 **CODEX 文本路由 + `-critic-shadow`** 过滤旁路请求：保留原始审计文件与尝试数据，未伪造任何审核成功回执。

## 四槽闭环

**① 原生 Codex 正式首帧链：** 单次正式 Driver start 已执行并有真实状态证据；新测试覆盖旧 WORK shadow 不阻断 CODEX，同时强制保留正式 story-semantic 审核。任何模型图片调用必须走 canonical Gateway、MySQL Generation Attempt、全局共享五图 permit；这轮没有脱离 Driver 的裸 Codex 图片调用，不得把 CLI 登录视为图片授权成功。

**② 持久化 Watchdog：** 真机曾返回 `REGISTERED` 但随后核验为 `FOREIGN_TASK`；原因是 Windows Task Scheduler 规范化了同一登录用户的名称。原计划使用字符串比较，错误拒绝任务。R9 改为最后在 Windows 原生 SID 上比对任务 principal 与独立验证的交互账号身份，并且安装后强制读回已注册任务的可执行文件、argv、工作目录、用户 Logon Trigger、IgnoreNew 单例与 Enabled 位。SID 无法确认或任意字段不一致严格拒绝；不得仅对比末段用户名。正式安装结果必须复查为 `INSTALLED`，不能以注册命令返回 0 当成真实验收。

**③ 实时 MySQL 与回执：** `scripts/storyos_autonomy_production_probe.py` 从被正式 runtime.env 包装的 canonical Driver、MySQL Stage 和 Attempt 只读权威读取；将 `RUNNING_RETRY_WAIT` 与实际图片结果分离，带 UNKNOWN 的 Attempt 一律标记人工 reconcile，绝不自动付费重试。对于 MySQL `PUBLISH_READY`，仅表示阶段真实到达，不伪造首帧像素审核证据。所有终态保留 `model_calls=0`、`sql_writes=0`。

**④ 测试与 Git GC：** R9 各槽 RED→GREEN，整轮 `--slot all` + `--stress` 保留先前 Runtime/恢复/五图共享容量基线。真正安全删除 3 个已合并、无工作树绑定的历史本地分支；其余历史 Worktree 因条件不满足全部保留。隔离本轮改造 Worktree 在合并/推送/确认干净后由 Git 非 force 退役。
