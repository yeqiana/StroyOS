# StoryOS R11｜授权生产：真实 Episode 迁移证据、安全对账与四槽极限验收

2026-10-13｜本轮用户授权生产，原生 Codex CLI 登录；所有实际模型及 MySQL 修改都必须服从 canonical Story Critic / Generation Attempt / 五图容量上限。绝不使用 OpenCodex。

## 实机核查：根因不是旧审核内容完全消失

目标 Episode：`episodes/15_天界生活日常/01_天界普通女生的一天`。

- 官方 MySQL Stage = `STORYBOARD_LOCKED`；图片 Attempt = 0；Driver 当前未运行；Windows Watchdog 任务 = `INSTALLED`；Story Critic read-only 判为 `FINALIZED_REVIEW_WITHOUT_CANONICAL_PROOF`，第 1 次请求 AWAITING，第 2 次 FINALIZED。
- 文件 `meta/story-semantic-review.json` **实际存在且声明审核 PASS**，Critic 来源为 `WORK_DEVSPACE_BOUNDED`、attempt=2、request_id 与第 2 次 FINALIZED 请求一致；故事与分镜 SHA 与现有文件一致，`story_review.validate_payload` 0 错误。
- 作品已由 `episodes/天界普通女生的一天/` 移至 `episodes/15_天界生活日常/01_天界普通女生的一天/`。正式 `release-manifest.json` 与旧 Review request 的文件路径没有迁移。Git commit `69e7a2a8` 显示三份 docs 文件的原始 blob 与迁移后 HEAD blob 一致：非文本修改，属于原字节迁移。
- 但**旧审核冻结的根目录《制作规范_正式版.md》SHA 与当前生产规范 SHA 不一致**。因此不能将旧 PASS 当作已经按最新版 rubric 审核。即使 legacy Review 的原始内容通过 schema/source/provenance 验证，也不得在未核对整个冻结来源的条件下自动写入新 MySQL 作为当前 PASS。该问题必须走新审核权威来源/独立策略修订程序。
- 目标 Episode 还没有冻结的当前 model policy SHA。任何历史 PASS 的原始校验都**不是**当前模型权限或质量审核通过的证明。

## 槽位一：变更受限的 Git 文件路径恢复

`scripts/storyos_manifest_relocation.py`：先读取原 Manifest、request#2 和 Git 迁移提交，保证三份文件在 commit 69e7a2a8 的 old→new blob 完全相同；故事与分镜还必须命中第 2 次审核请求的冻结 SHA。只读 `plan` 不写任何文件；执行 `--apply --ack-real-production` 时额外检查主工作树、两次来源快照、无活动 Driver、精确原 Manifest SHA，然后**只修改 `meta/release-manifest.json` 的三个 artifact 路径**。不修改任何故事文本、分镜、审核请求、review payload、MySQL、图片 Attempt、字幕或像素准入。

`scripts/storyos_relocated_review_recovery.py` 是独立的**严格冻结来源证据**审计：除了三个 Git 文件迁移，还核对历史正式审核的全部冻结规范文件 SHA。对当前 Episode 得出 `CRITIC_SOURCE_SHA_DRIFT`，因此不会把旧审核结果复制到 MySQL。只有全部冻结来源都不变、原 Reviewer/请求/来源 SHA 重新确认且无并发 Driver，才允许显式受控重建原本存在的 REVIEW 投影；任何写入后都必须重新读取正式 MySQL 和 Story Review Gate，失败不能声称恢复成功。

## 槽位二：Driver/Watchdog 恢复的 fail-closed 联合判断

`scripts/storyos_autonomy_resume_admission.py` 联合 canonical MySQL Driver/Attempt 状态、Story Review lifecycle 和 Manifest 来源状态；如果 MySQL Attempt 仍 UNKNOWN、Stage 未证实或官方 Story Review 缺失，一律不给自动分发权限。即使源路径修复，仍继续等待正式独立 Reviewer，不能把这个问题归入可自动重试的 transient rc=3。

## 槽位三：PREIMAGE、M00、Frame01 约束维持不变

新的恢复/迁移脚本一律输出 `can_dispatch_image=false`、模型调用数 0；每一次 Provider 图片调用必须由现有 canonical Gateway/Attempt/Fence 和共享五图 Permit 执行。路径迁移不等于 M00 像素审核成功，也不授权单帧付费生图。
