# M00 外部参考图绑定与传输验收 R3

这套机制**只学习真实摄影行为、成像质感、自然光及物理缺陷**，不从示例图片引入人物、情节、动作、道具、地点、特定设备年代或人物数量。

## 当前状态和源文件边界

用户在对话中提供的 7 个原始附件已可在对话文件空间读取并计算 SHA；但 WebCodex 原生附件导入遇到 `download_link host is not an OpenAI file host`，因此正式工作区尚未持有原始附件，**不得声明 Provider 收到了图像参考**。

不把用户图像二进制提交进 Git，不写公开固定题材的提示词，不修改任何已有 Episode 与 MySQL 阶段。工作区只能从用户原始文件构建私有 staging。

## 安全地导入本机图片

将用户原始文件和 `manifest.json` 放到同一个本地目录。每份 manifest.uploads 包含原始 `filename`、`sha256`、`source_attachment_id`。

```powershell
# 校验附件来源与 SHA，不写文件
python scripts/storyos_m00_reference_stage.py --source-dir <源目录> --manifest <manifest.json>

# 只有确定在 StoryOS 主工作区执行时才复制到未纳入 Git 的私有目录
python scripts/storyos_m00_reference_stage.py --source-dir <源目录> --manifest <manifest.json> --apply
```

执行结果是相对路径与 SHA 的引用目录，**不会自动写某集的 user-visual-reference-contract 或启动图片生成**。最终给 Episode 绑定时，需要该集显式的合同，按原有 `USER_VISUAL_REFERENCE` 审计入口保存，并保留：

- `kind=capture_style`
- `origin=direct_user_upload`
- `reference_use=capture_appearance_only`
- `source_attachment_id=file_...`
- `decision=locked`
- `path` 必须位于 `.storyos/user-visual-references/`
- `sha256` 与本地实际文件完全一致

这些标注仅允许**声明为用户外部原图的来源**；不是角色一致性参考、不是审批权威、也不授权生成 Attempt。

## 生产证据

常规 Reference Arbitrator 全局最多两份图片参考，人物身份需求优先，外部 capture_style 不得挤掉锁定身份。
生成 Controller 的 Payload Request 记录每个引用 SHA；Provider 回执必须**一一对应所有声明引用**，少传、多传、重复、哈希漂移均为未验证。回执本身只能证明本地执行记录，不能凭固定字符串断言远端 Provider 已物理接收（缺失服务端证明时维持未确认）。
