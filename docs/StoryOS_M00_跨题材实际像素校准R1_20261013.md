# M00 实际像素跨题材校准 R1（2026-10-13）

## 核心边界

M00 是纪实拍摄与设备物理规范，**不是场景、事件、动作、人物数量、摄影设备型号的固定模板**。

测试样本放在 `tests/fixtures/m00_pixel_calibration_samples.json`，只引用历史 Approved 的文件路径与 SHA，用于发现潜在过度电影化、幽灵机位、无来源布光、静止画面被错误判废等问题。样本不进入 Story、Frame Contract、生成 Prompt、人物身份母版或生产 Reference。历史 Approved ≠ 本轮像素风格通过。

## 使用方法

此命令只读图片、计算 SHA/尺寸/解码状态；没有实际视觉理解模型，不会将“文件尺寸合规”伪装成“风格 PASS”。

```powershell
# 在持有原始 Approved 资产的 StoryOS 本地工作区运行
python scripts/storyos_m00_pixel_calibration.py

# 从隔离工作树读取主工作区的既有图像时
python scripts/storyos_m00_pixel_calibration.py --asset-root "D:\\workspace\\YeQianWorkSpace\\yeqian\\storyOS"

# 极速测试，不产生图片、不触及 MySQL
python -m unittest tests/system/test_m00_pixel_audit.py -v
python scripts/storyos_m00_fast_test.py

# 有自动化消费方时才使用；任何缺图/漂移/未看全图都会以非零退出
python scripts/storyos_m00_pixel_calibration.py --strict
```

未找到图片 -> `SOURCE_MISSING`；SHA 漂移 -> `SOURCE_SHA_DRIFT`；图片正常但无人审 -> `NEEDS_PIXEL_REVIEW`；仅预览评审 -> `FULL_IMAGE_REVIEW_REQUIRED`。只有提供六维人工/模型实际像素评审、来源 SHA、审核者、观察及全图依据后才可得到 **`ADVISORY_PIXEL_PASS`**，仍**不授权 Visual Lock、Episode Stage 或发布**。

正式像素评审仍由 StoryOS 原有四张 Visual Lock + Final Critic 等原有 Gate 授权。采用一组多样本是为了发现不同拍摄条件下的偏差，不是为了将示例情节复制到下一篇。
