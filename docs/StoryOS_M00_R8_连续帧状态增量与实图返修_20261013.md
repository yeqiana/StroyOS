# StoryOS M00 R8 · 四槽连续帧状态变化与实图返修（2026-10-13）

本轮修复 R7 真图问题：C02-R2 → S01 人物、车、巷子保留但脚步/车轮几乎没有推进；S01 → S02 有动作却出现右墙、门口和盆栽的无依据重构。两个历史 Pair Review 都是 **REPAIR_RECOMMENDED**；不能以“图片返回成功”冒充视觉通过。

## 四槽交付

1. **身份与背景锁定。** 通用 `m00_sequence_state_delta.py` 要求明确人物/衣物/道具/地点/摄影者/光线六类源故事锁定值。真实测试 R8 以已有 C02-R2 PNG 为 `identity`，只取一张用户原始风格图为 `capture_style`，保留两类引用角色、源图 SHA 及 CP02 设备物理。参考图没有授权改变故事事件或人物来源。
2. **状态增量与静止豁免。** 每个行动中的相邻帧必须有前状态、后状态、实际像素证据；不能只说“再往前一步”。但原剧本如果是静态镜头，`mode=static` 合法，禁止发明步行、模糊或异常。所有增量事实属于具体锁定的帧/故事，不强加到 M00 母风格。
3. **真实像素与审核。** `storyos_m00_sequence_r8.py review` 只读核对两图 SHA、原生 Test-only 回执和生成时 request_identity；需要明确人工完整原图逐项审核才能给出 **ADVISORY_PAIR_PASS**（始终不能升级为正式 Stage/Visual Lock/Release）。对完全相同的行动图立即输出 `IDENTICAL_PIXELS_DO_NOT_PROVE_NEW_ACTION`；64×64 粗略 RGB 差异仅是诊断数值，既不证明动作推进，也不证明背景正确，绝不能用阈值伪造质量合格。
4. **原生 Codex 调度与安全修订。** 新图编号 `C02-T01`，只依赖旧的、通过图片 SHA 校验的 C02-R2 原图，是一次全新 Test-only 对照修订；它**不是旧 S01/S02 的再次调用，也不是对失败配对审核填写虚假 PASS**。经 R6 共享容量 `image_permits`、独占一次派发回执、用户已登录的原生 Codex Bridge。超时保持 UNKNOWN，不自动重发；无需 MySQL 正式 Review Authority，但没有正式生产许可。
